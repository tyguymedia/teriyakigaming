Inkwell is a self-contained code-plus-content plugin for Unreal Engine 5.7. It depends
only on engine modules — no other plugins, no third-party libraries — so installing it
never pulls anything else into your project.

## Installing from Fab

After acquiring Inkwell on Fab, install it to your engine through the Epic Games
Launcher (your Fab library → install to the engine version your project uses), then
launch the editor.

Alternatively, you can use Inkwell as a **project plugin**: copy the `Inkwell` plugin
folder into your project's `Plugins/` directory and restart the editor. This is handy
for teams that vendor plugins in source control, and it is how the
[demo project](https://github.com/tyguymedia/Inkwell) ships it.

## Enabling the plugin

The plugin declares `EnabledByDefault`, so in most setups it is active as soon as it is
installed. To check or change this per project, open **Edit → Plugins**, find **Inkwell**
under the *Content* category, toggle it, and restart the editor when prompted.

You'll know it's active when:

- a **Page Editor** dropdown button appears in the Level Editor toolbar,
- **Tools → Inkwell** appears in the main menu, and
- **Inkwell → Page Document** appears in the Content Browser's right-click *new asset*
  menu.

<Tip>
If your toolbar is crowded, you can hide the toolbar button with **Project Settings →
Plugins → Inkwell → Show Toolbar Button** (takes effect after an editor restart). The
Page Editor stays reachable by double-clicking a Page Document, from **Tools → Inkwell**,
and via the `Inkwell.OpenPageEditor` console command.
</Tip>

## What's inside the plugin

| Module | Type | Loading phase | Contents |
|---|---|---|---|
| `Inkwell` | Runtime | `PreDefault` | Everything your game uses: the Ink Page Document asset class, the display/stack/reader/interactor components, the Ink Page actor, the UMG page widget, the bake pipeline, and the project settings. Ships in packaged builds. |
| `InkwellEditor` | Editor | `Default` | The WYSIWYG Page Editor window, the Page Document asset definition and factory, the Content Browser / toolbar / Tools-menu integration, and the font import tooling. Automatically stripped from packaged builds. |

The runtime module's only dependencies are engine modules (`Core`, `CoreUObject`,
`Engine`, `InputCore`, `Slate`, `SlateCore`, `UMG`, `DeveloperSettings`, plus private
`RenderCore` and `RHI`), which is what "zero project dependencies" means in practice.

The plugin also contains content (`CanContainContent`), mounted at `/Inkwell/`: the page
materials, the 100 cm page sheet mesh, paper and blank-ink textures, five bundled font
families, and the example content under `/Inkwell/Examples/`. Enable **Show Plugin
Content** in the Content Browser to browse it under **Plugins → Inkwell Content**.

## Project Settings → Inkwell at a glance

Everything the plugin loads resolves through **Project Settings → Plugins → Inkwell**
(`UInkwellSettings`), so a project can repoint any asset — its own ink material, its own
paper texture, its own default font — without touching code. Inkwell never hard codes a
content path. Settings are `defaultconfig` (config `Game`), so changes are written to
your project's `Config/DefaultGame.ini` and travel with source control.

The full reference lives in [Settings](/plugins/inkwell/reference/settings); this is the shape of it:

### Materials

| Setting | Default | What it does |
|---|---|---|
| Page Ink Material | `/Inkwell/Materials/MI_PageInk` | Base material used to display baked pages on meshes. Must expose the parameters named under *Material Parameters*. Repoint it to use your own page material (for example a lit parchment shader). |
| Page Preview Material | `/Inkwell/Materials/M_PageComposite_Preview` | Unlit twin used only by the Page Editor's live preview, so the editor shows the exact multiply the game does. Unset, the editor falls back to a paper + ink alpha stack. |

### Material Parameters (advanced)

The parameter names Inkwell drives on your page material. Defaults match the bundled
material: `InkTexture`, `PaperTexture`, `UsePaperTexture`, `PaperTint`, `InkTint`,
`InkStrength`. Change these only if your own material names them differently.

### Content

| Setting | Default | What it does |
|---|---|---|
| Page Sheet Mesh | `/Inkwell/Meshes/SM_PageSheet` | Default mesh for page sheets. Must have clean 0–1 UVs across the page face — atlas-mapped prop meshes garble page content. |
| Default Paper Texture | `/Inkwell/Textures/T_PaperPlain` | Paper albedo used when a Page Document does not specify one of its own. |
| Blank Ink Texture | `/Inkwell/Textures/T_InkNone` | Fully transparent texture assigned to sheets with no content yet, so a bare sheet renders as blank paper. |
| Default Page Font | `/Engine/EngineFonts/Roboto` | Font used by documents whose own Default Font is unset. Point it at one of the bundled fonts (for example `/Inkwell/Fonts/Font_CrimsonText`) to change the project-wide look of every unstyled run in one place. |

### Fonts

| Setting | Default | What it does |
|---|---|---|
| Font Search Paths | `/Inkwell/Fonts`, `/Game` | Content paths scanned for composite fonts to list in the Page Editor's font picker. Keep the list tight on large projects — every font found is loaded to read its typeface names. |
| Include Engine Fonts | `true` | Also list the engine's built-in fonts (Roboto) in the picker; they always sort last. |
| Font Build Output Path | `/Game/Fonts` | Where font import writes the composite font assets it generates. Must be a writable *project* path — plugin content is read-only in a shipped plugin install. |

### Rendering

| Setting | Default | What it does |
|---|---|---|
| Max Page Bake Dimension | `4096` (clamped 64–8192) | Safety clamp on page bake resolution, per axis. A document asking for more is clamped rather than allocating a render target of hundreds of megabytes. |
| New Document Page Size Pixels | `1024 × 1400` | Page size assigned to newly created Page Documents. |

### Editor

| Setting | Default | What it does |
|---|---|---|
| Show Toolbar Button | `true` | Show the Inkwell button in the Level Editor toolbar. Takes effect after an editor restart. |

<Note>
If a required setting is cleared or its asset fails to load, Inkwell logs one warning per
session naming the exact setting to fix (for example *"Set 'Project Settings > Plugins >
Inkwell > Page Ink Material'"*) rather than failing silently.
</Note>

## Packaging considerations

Inkwell is built to package cleanly, but a few mechanics are worth knowing:

- **The editor module strips itself.** `InkwellEditor` is an Editor-type module, so
  authoring tools never end up in a shipping build. Everything the game needs — baking
  included — lives in the Runtime module.
- **Fonts are cooked via `FontReferences`.** Rich-text markup stores fonts as *string
  paths*, which the cooker cannot see. Each Page Document therefore carries a
  **Font References** array of hard references, maintained automatically by the Page
  Editor on save — without it, fonts used only by styled runs would be cooked out and
  every styled run would fall back to the default font in a packaged build. You don't
  need to touch it; just don't delete it.
- **Runtime-built documents referencing fonts by path.** If you build markup at runtime
  (see [Runtime documents](/plugins/inkwell/guides/runtime-documents)) with fonts that no cooked asset
  hard-references, make sure those fonts are otherwise referenced or added to your
  cook — the string path alone will not pull them in.
- **Settings assets are soft references.** The defaults live in plugin content and cook
  with it. If you repoint a setting at a project asset that nothing else references,
  confirm it is included in the cook (for example via *Additional Asset Directories to
  Cook*).
- **Pages bake at runtime.** Baked ink render targets are produced in game via a
  per-world cache (Game and PIE worlds), keyed so edited documents regenerate cleanly.
  **Max Page Bake Dimension** caps the memory a single page can claim. Details in
  [How rendering works](/plugins/inkwell/reference/rendering).
- **Demo input stays optional.** The interactor's **Enable Default Input** key bindings
  are plain runtime bindings, not editor features — remember to turn them off when you
  ship your own input, or the demo keys stay live in the packaged game.
