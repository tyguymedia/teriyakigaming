description: "Create a page, write on it, and put it in your level — a readable note in about ten minutes"

By the end of this page you will have written a note in the Inkwell Page Editor and be
standing in front of it in your own level, reading it. No C++, no Blueprint graph, and
nothing to configure first.

If the plugin is not installed and enabled yet, do [Installation](/plugins/inkwell/installation) first —
this page assumes the **Page Editor** button is in your Level Editor toolbar.

<Steps>
  <Step title="Create an Ink Page Document">
    In the Content Browser, right-click in the empty space of a folder in your project and
    choose **Inkwell → Page Document**. Name the asset and press Enter.

    That asset (`UInkPageDocument`) is the content: every page, every layer, the paper and
    the default text style. A new one is seeded from your project settings so it renders
    something immediately — a 1024 × 1400 px page, the bundled plain paper texture, and
    the project's default font at Regular weight. It opens straight into the Page Editor.

    <Accordion title="Other ways to create one">
      From the Level Editor toolbar, open the **Page Editor** dropdown and choose
      **New → Create New Page Document...** — you get an asset-save dialog, and the new
      document opens in the editor when you confirm.
    </Accordion>
  </Step>

  <Step title="Open the Page Editor">
    If the editor did not already open, double-click the Page Document asset. It opens a
    window titled **Inkwell Page Editor — *YourAssetName***.

    Three other routes reach the same window, which matters once a project has more than a
    handful of documents:

    - **Content Browser:** right-click the asset → **Edit Pages...**
    - **Level Editor toolbar:** the **Page Editor** dropdown → **Edit Document...** for a
      browser dialog, or **Recent / All Documents** for the documents you edited recently
      plus a filter-as-you-type list of every one in the project.
    - **Level viewport:** right-click a placed actor that references a document →
      **Inkwell → Edit Pages (*DocumentName*)...**. An actor referencing more than one
      document gets an **Edit Pages** submenu listing them instead.

    <Frame caption="The Inkwell menu, from the Page Editor button in the Level Editor toolbar. Recent / All Documents opens the searchable list.">
      <img src="/images/inkwell/toolbar-dropdown.png" alt="The Inkwell menu: Edit Document, Recent / All Documents, Create New Page Document, Import Font Family" />
    </Frame>

    The window opens in three resizable panes. Drag the splitters — none of them can be
    dragged shut.

    <Frame caption="The Page Editor, with the three panes it opens in.">
      <img src="/images/inkwell/page-editor-overview.png" alt="The Inkwell Page Editor window" />
    </Frame>

    <Steps>
      <Step title="1 — Left panel">
        Everything about the document: **Pages** (add, duplicate, delete, reorder),
        **Page Setup** (Size px, Width cm, Margins, Line height), **Paper & Ink**,
        **Default Text Style**, **Drawing Tools**, and the **Save Document** button at the
        bottom.
      </Step>
      <Step title="2 — Toolbar">
        Styling for the text you have selected: font family, size, **B** / **I** / **U** /
        **-S-**, text color, and the three justify buttons. On the right, **Mode**
        switches the page surface between **Text**, **Image** and **Draw**.
      </Step>
      <Step title="3 — The page">
        The paper itself, at the shape you authored. In Text mode you click into it and
        type; each text box is outlined so you can see where it ends.
      </Step>
      <Step title="4 — Right panel">
        **Rendered Preview (game-true ink)** on top — the page put through the same bake
        path the game uses — and **Layers (front to back)** underneath.
      </Step>
    </Steps>
  </Step>

  <Step title="Write on the page">
    Click on the paper and type. A new document opens with one Text layer that fills the
    page inside the document margins, so you can start writing immediately.

    Then style it:

    - Select some text and pick a **font family** from the toolbar dropdown. The five
      bundled families are listed first; the engine's Roboto sorts last.
    - Set a **size**, toggle **B** / **I** / **U** / **-S-**, or click the color block to
      recolor the selection. Bold and italic need a Bold or Italic face in the chosen
      family — Courier Prime and Crimson Text ship all four, Kalam ships Regular and Bold,
      and Great Vibes and Patrick Hand ship a Regular face only.
    - The justify buttons align the text box the caret is in, not the whole page.

    Watch the **Rendered Preview** on the right as you go. It refreshes a few times a
    second and is the truth: if a font falls back or a color reads wrong there, it will
    read wrong in game.

    <Tip>
    Every edit goes onto the editor's normal undo stack, and it is grouped sensibly: a
    slider drag is one undo step rather than one per tick, and a burst of typing is one
    step rather than one per keystroke. The Page Editor window binds no shortcut of its
    own — undo and redo from the main editor window (**Edit → Undo** / **Edit → Redo**),
    and the Page Editor re-reads the document and updates.
    </Tip>

    When you want more than one block of text, an image, or something drawn by hand, use
    the buttons under the Layers list: **+ Text**, **+ Image**, **+ Drawing**. See
    [Layers](/plugins/inkwell/authoring/layers), [Drawing](/plugins/inkwell/authoring/drawing) and
    [Paper](/plugins/inkwell/authoring/paper) — none of it is needed for this walkthrough.
  </Step>

  <Step title="Save Document">
    Click **Save Document** at the bottom of the left panel.

    It does three things: commits whatever you were typing, rebuilds the document's hard
    font references, and saves the asset.

    <Warning>
    Save from that button rather than from the Content Browser. Rich-text markup stores
    fonts as string paths, which the cooker cannot see — **Save Document** is what
    refreshes the document's **Font References** list so those fonts get cooked. Skip it
    and styled runs fall back to the default font in a packaged build.
    </Warning>
  </Step>

  <Step title="Put the page in your level">
    Two routes. Take the first if you want paper in the world; take the second if the note
    belongs on a prop, a desk, a clipboard or a corkboard you already have.

    <Tabs>
      <Tab title="Drop in an Ink Page actor">
        Open the **Place Actors** panel (**Window → Place Actors**), search for
        **Ink Page**, and drag it into your level. It is the ready-made single sheet
        (`AInkPageActor`) and lands as a flat piece of paper.

        With it selected, find the **PageDisplay** component in the Details panel's
        component list and set its **Document** to your new asset. The writing appears on
        the sheet immediately — the display component previews in the editor viewport, no
        Play needed.

        The sheet then sizes itself: **Page Width Cm** from the document (21 cm, the width
        of A4, unless you changed it) with the height following the page's shape. Two knobs
        adjust this copy without touching the document:

        | Property | Where | What it does |
        |---|---|---|
        | **Page Scale** | the PageDisplay component | 1 is the document's own size, 2 twice as big, 0.5 half. Scales both axes together, so the writing never stretches. |
        | **Page Yaw** | the actor, under *Inkwell \| Sheet* | Spins the sheet about its own normal so the writing reads upright for your scene. |
      </Tab>

      <Tab title="Add a display to an actor you already have">
        Select the actor in the level (or open its Blueprint), click **Add Component**, and
        add **Ink Page Display**. Set its **Document** to your asset.

        **Procedural Paper** is on by default, and it is what makes this a one-property
        setup: if the actor has no mesh of its own, the component spawns a paper sheet,
        attaches it to the actor's root, and sizes it from the document. Swap in a document
        authored at a different size and the sheet resizes, live in the viewport.

        It never takes a mesh away from you. If the actor already has a mesh component — or
        you pick one in **Target Mesh** — the page is drawn onto that instead and no sheet
        is spawned. Turn **Procedural Paper** off to leave a mesh-less actor drawing
        nothing.

        <Warning>
        Drawing onto your own mesh needs clean 0–1 UVs across the page face. An
        atlas-mapped prop mesh will garble the text, because the baked ink is sampled
        across the full 0–1 range. If the prop has several material slots, set
        **Material Slot** to the one the paper face uses.
        </Warning>

        <Accordion title="Nothing appeared on the actor">
          - No mesh, and **Procedural Paper** turned off: the component has nowhere to
            draw. Turn it back on, or set **Target Mesh**.
          - The page landed on the wrong material slot — **Material Slot** is 0 by default.
          - **Preview In Editor** (advanced) is off: the page still appears in Play, but
            not in the viewport.
        </Accordion>
      </Tab>
    </Tabs>
  </Step>

  <Step title="Walk up to it">
    Press Play and walk over to the page. It is real geometry at the size you authored, so
    it reads from a normal standing distance — and lean in and the strokes hold, because
    the ink is baked at the document's own pixel resolution rather than stretched from a
    small texture.

    <Frame caption="The finished note, placed in the level and readable in the world.">
      <img src="/images/inkwell/note-in-level.png" alt="An Inkwell note placed in a level" />
    </Frame>

    To let the player *pick it up* — float it in front of the camera, turn pages, put it
    back exactly where it lay — you need one more component, and which one depends on what
    your project already has:

    - **No interaction system yet:** add an **Ink Page Interactor**
      (`UInkPageInteractorComponent`) to your pawn. With **Enable Default Input** on (the
      default) it binds demo keys straight away: **E** to read, **Q** to close, **Left
      arrow** or mouse wheel down and **Right arrow** or mouse wheel up to turn pages. It
      traces 300 cm from the view every 0.1 s, and creates an Ink Page Reader for itself if
      the pawn has none.
    - **You already have one:** leave your interactor alone. Add an **Ink Page Reader**
      (`UInkPageReaderComponent`) to the pawn and call **Begin Reading** from your own
      interaction code. That is the [integration guide](/plugins/inkwell/guides/integration), and it is
      what most projects need.
  </Step>
</Steps>
