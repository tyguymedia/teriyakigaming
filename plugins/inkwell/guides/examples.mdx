Inkwell ships eight example assets inside the plugin: two finished
[Ink Page Documents](/plugins/inkwell/authoring/documents), a journal prop Blueprint, four Enhanced Input
actions, and a read-prompt widget. They exist so you can see the plugin working in a level
within a minute of enabling it, and so you have a finished document to pull apart in the
[Page Editor](/plugins/inkwell/authoring/page-editor).

There is **no demo map inside the plugin** — a plugin cannot ship a level without dragging
a project's worth of settings along with it. You place the example actors yourself, which
takes about thirty seconds, or you clone the separate demo project described at the bottom
of this page.

## Finding the content

<Steps>
  <Step title="Show plugin content">
    In the Content Browser, open the **Settings** menu and tick **Show Plugin Content**.
    Plugin folders are hidden by default, which is the single most common reason people
    think Inkwell shipped no examples.
  </Step>
  <Step title="Browse to the folders">
    In the source panel, go to **Plugins → Inkwell Content**. The two folders that matter
    here are **Examples** and **Demo**; asset paths are written as `/Inkwell/Examples/...`
    and `/Inkwell/Demo/...`.
  </Step>
</Steps>

## Everything that ships as an example

| Asset | Path | Type | Demonstrates |
|---|---|---|---|
| `DA_InkwellSample` | `/Inkwell/Demo/` | Ink Page Document | A short two-page note: styled runs, a center-justified text box, a per-page paper override |
| `DA_InkwellJournal` | `/Inkwell/Examples/` | Ink Page Document | A five-page journal: all five bundled font families, bold / italic / underline / strikethrough, colored ink |
| `BP_InkwellJournalStack` | `/Inkwell/Examples/Blueprints/` | Actor Blueprint | The minimum readable prop: an actor with an Ink Page Stack pointed at the journal |
| `IA_Interact` | `/Inkwell/Examples/Input/` | Input Action | Open the focused page / close the one being read |
| `IA_NextPage` | `/Inkwell/Examples/Input/` | Input Action | Turn forward |
| `IA_PreviousPage` | `/Inkwell/Examples/Input/` | Input Action | Turn back |
| `IA_PutBack` | `/Inkwell/Examples/Input/` | Input Action | Put the page being read back down |
| `WBP_InkwellReadPrompt` | `/Inkwell/Examples/UI/` | Widget Blueprint | A prompt and page counter driven by the Ink Page Interactor and Ink Page Reader |

Everything else in the plugin's Content folder — `Fonts`, `Materials`, `Meshes`,
`Textures` — is not example content. Those are the assets the runtime resolves through
*Project Settings → Plugins → Inkwell*, and Inkwell needs them. See
[Settings](/plugins/inkwell/reference/settings).

## DA_InkwellSample

`/Inkwell/Demo/DA_InkwellSample` — a two-page note, the shortest complete document in the
plugin. Double-click it to open the [Page Editor](/plugins/inkwell/authoring/page-editor).

- **Page 1** is a note in two voices: a Great Vibes heading (`for you`, 64 pt, in blue ink)
  over a Kalam handwritten body at 30 pt in the same blue.
- **Page 2** is center-justified, and its italic Crimson Text line says so: justification
  belongs to the text box it is set on, and the paper to the page — neither is a
  document-wide setting. It is the page to read if you are wondering what **Paper override
  (this page)**, in the Page Editor's **Paper & Ink** section, is for.

Both pages use the plugin's plain paper texture and the default 1024 × 1400 page at 21 cm
wide, so they render as A4-shaped sheets in the level.

**To place it:** open the **Place Actors** panel, search for **Ink Page**, and drag the
actor into the level. In its Details panel, set the Ink Page Display component's
**Document** to `DA_InkwellSample`. The sheet sizes and bakes itself immediately, in the
viewport, without pressing Play.

</Frame>

## DA_InkwellJournal

`/Inkwell/Examples/DA_InkwellJournal` — the five-page journal the stack Blueprint displays,
and the best single reference for what an authored document can look like. Each page
deliberately uses a different hand so you can see all five bundled font families and every
text style in one document:

1. **Title page** — "The Keeper's Journal" in Great Vibes at 68 pt, an italic Crimson Text
   subtitle, and a small Patrick Hand line telling the player to turn pages with the arrow
   keys.
2. **A handwritten entry** — Kalam, with a bold heading, body text at 30 pt, and a blue
   margin note in a smaller size.
3. **A typed log** — Courier Prime, showing a **strikethrough** run struck through one line
   of the inventory and a red correction beside it.
4. **A letter** — Crimson Text, mixing regular, italic and bold runs inside single
   paragraphs, and closing on a bold, underlined line in red — the one Kalam line on the
   page.
5. **A closing page** — "finis" in Great Vibes over an italic sign-off.

Open it and click into any run: the toolbar shows the exact font, typeface, size, and color
that run carries, which is the quickest way to learn how the
[markup](/plugins/inkwell/guides/runtime-documents#the-markup-format) is put together.

## BP_InkwellJournalStack

`/Inkwell/Examples/Blueprints/BP_InkwellJournalStack` — an Actor Blueprint with exactly two
things in it: a default scene root, and an **Ink Page Stack** component named `PageStack`
with its **Document** set to `DA_InkwellJournal`. There is no Event Graph logic at all.
That is the point: a readable multi-page prop is a component and a document reference.

**To place it:** drag the Blueprint from the Content Browser into the level. The journal
appears as a physical pile of sheets, one mesh per page, the current page on top and the
rest squared up underneath. With an [Ink Page Interactor](/plugins/inkwell/components/interactor) on your
pawn — or your own interaction system calling
[Begin Reading Actor](/plugins/inkwell/guides/integration) — it is immediately readable.

<Frame caption="BP_InkwellJournalStack in a level: one sheet mesh per page, current page on top.">
  <img src="/images/inkwell/journal-stack-in-level.png" alt="The Inkwell journal page stack lying in a level" />
</Frame>

It is also a live playground for the stack's look. Select the placed actor and drag **Sheet
Gap**, **Fan Splay**, **Fan Angle**, **Stack Yaw**, or **Page Turn Duration**: the pile
re-lays itself in the editor viewport as you drag, no PIE needed. See
[Ink Page Stack](/plugins/inkwell/components/page-stack) for what each property does.

## The Enhanced Input actions

`/Inkwell/Examples/Input/` holds four Input Action assets: `IA_Interact`, `IA_NextPage`,
`IA_PreviousPage`, and `IA_PutBack`. All four are **Digital (bool)** actions with a single
**Pressed** trigger — the plainest possible button actions.

<Note>
**No Input Mapping Context ships with them, and no keys are bound.** An IMC is a
project-level decision, and shipping one would either collide with yours or quietly do
nothing. Add mappings for these four actions to your own Input Mapping Context, or make
your own actions and ignore these entirely — they carry no logic, only names.
</Note>

They line up one-to-one with the Ink Page Interactor's Blueprint functions:

| Action | Call on the interactor | Or, without the interactor |
|---|---|---|
| `IA_Interact` | **Interact** | Ink Page Reader → **Begin Reading Actor** / **End Reading** |
| `IA_NextPage` | **Next Page** | Ink Page Reader or Ink Page Display → **Next Page** |
| `IA_PreviousPage` | **Previous Page** | Ink Page Reader or Ink Page Display → **Previous Page** |
| `IA_PutBack` | **Stop Reading** | Ink Page Reader → **End Reading** |

## WBP_InkwellReadPrompt

`/Inkwell/Examples/UI/WBP_InkwellReadPrompt` — a Widget Blueprint with a canvas holding two
text blocks, `Crosshair` and `PromptText`, and two variables, `Interactor` and `Reader`.

How it works: it caches the pawn's two Inkwell components into the `Interactor` and `Reader`
variables (**Get Owning Player Pawn** → **Get Component by Class**, whose return pin is
already typed from the Component Class pick, so no cast is needed), then on **Tick**
branches on the reader's **Is Reading**:

- **Reading** → the prompt reads
  `Left / Right : Turn page      E : Put back      Page N / M`, where N and M come from the
  reader's **Get Current Page** → **Get Current Page Index** (plus one) and **Get Page
  Count**. The crosshair's render opacity is set from the same branch.
- **Not reading** → if the interactor's **Get Focused Page** is valid the prompt reads
  `E : Read`; otherwise it is collapsed.

Add it to the viewport from your player Blueprint (**Create Widget** → **Add to Viewport**)
and it works with no other setup, provided the pawn carries both components.

<Warning>
This widget is written the short way, on Tick, and its key names are hard-coded into the
prompt strings to match the interactor's demo bindings (**E**, Left / Right). It is a demonstration, not a
production HUD. In a real project, bind the interactor's **On Focus Changed** and the
reader's **On Reading Started** / **On Reading Ended** events instead of polling, and get
the key names from your own input system.
</Warning>

## What to copy, and what to leave

| Asset | Copy it into your project? |
|---|---|
| `BP_InkwellJournalStack` | **Copy the pattern, not the asset.** It is two clicks to rebuild: an actor, an Ink Page Stack, a document. Copy the asset only if you want a prop to hack on. |
| `DA_InkwellSample`, `DA_InkwellJournal` | **Reference or copy freely.** Both are ordinary Ink Page Documents. Copy one into `/Game` and edit it as a starting template; the five bundled fonts they use are open-licensed and ship with the plugin. |
| `IA_*` input actions | **Fine to reference directly**, or copy into `/Game` if you would rather own them. They contain no logic. |
| `WBP_InkwellReadPrompt` | **Demo only.** Read it, do not ship it. See the warning above. |

<Tip>
Copy anything you intend to modify into `/Game` first (right-click → **Duplicate**, or drag
into a project folder). Assets in the plugin's own Content folder are replaced when you
update Inkwell, and any edits you made to them go with the old version.
</Tip>

## The demo project

A complete demo *project* — the plugin plus a working first-person setup — lives separately
at [github.com/tyguymedia/Inkwell](https://github.com/tyguymedia/Inkwell). It is not part of
the Fab download; clone it if you want to see the whole wiring in one place rather than
build it.

What it adds on top of the plugin:

- **A level** (`Lvl_FirstPerson`, the FirstPerson template map) with an **Ink Page** actor
  showing `DA_InkwellSample` lying on a surface, and a `BP_InkwellJournalStack` placed
  nearby — the two screenshots on this page.
- **A first-person character** carrying an Ink Page Interactor (`PageInteractor`) and an
  Ink Page Reader, with **Enable Default Input** turned off, binding the four example input
  actions to the interactor's functions through Enhanced Input events, and creating
  `WBP_InkwellReadPrompt` on screen.
- **`IMC_Default`** with key mappings added for `IA_Interact`, `IA_NextPage`,
  `IA_PreviousPage`, and `IA_PutBack`, alongside the template's own move and look mappings.

That character is the interactor-based path spelled out end to end. If your project already
has its own interaction system, the path you want instead is
[Integrating with your interaction system](/plugins/inkwell/guides/integration), which skips the interactor
entirely.
